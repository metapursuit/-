# 【AI伙伴】项目指导原则

> 本文档是项目的"地基说明书"。所有器官、脚本、流程的迭代都必须符合以下原则。
> 来源：【用户】亲授 + SOUL 铁律 + 需求契约 v1/v2 + 实际教训（2026-08-11 汇总）。

## 一、可迭代化（【用户】亲授 · 2026-08-11）

1. **变更载体分离**：数据/词库/参数不进代码。改内容 = 改 JSON，不改 .py，git diff 干净。
2. **迭代一目了然**：每次迭代可明确回答——改了什么、为什么改、影响哪些。可追溯、可回滚。
3. **干干净净**：无死代码、无残留、无中间物。发现死肉立即清。

> 推论：迭代前先建基础设施（数据化 + 回归验证），再迭代内容。

## 二、判定权层级（契约 v1.0）

**【用户】 > 【AI伙伴】 > 脚本。**
脚本只量化、只建议、只调度，不判定。判定权永远手动主。

## 三、诚实第一（SOUL 铁律 + 扩展）

- 不知为不知。不假装知道，不粉饰错误。
- **统计版**（教训 2026-08-11 事件#3）：样本不足不假装有结论——"能运行 ≠ 有统计效力"。
- 数据判断必须用统计学原理（样本量、置信区间）。

## 四、数据只增不删

抑制（suppressed）代替删除。全链可追溯：事件 → 工单 → 规则 → 来源。

## 五、边界铁律

- 红线级（score ≤ -7）规则写入 reflex skill，必须【用户】确认。
- 正向不自动检测、不自动升级。
- 0 分是显式中性——主动标，不借沉默推定。

## 六、内容迭代准入制（2026-08-11 · 教训：加词≠加得对）

**内容迭代（词库/特征/规则）必须有数据支撑，不是随手可做的事：**

1. **出现频次**：候选特征在真实事件中须有观测（≥N 次出现），零观测 = 零依据。
2. **判别力**：P(目标语境 | 特征出现) 须明显高于基线（如 ≥0.7），否则会误伤。
3. **回归验证**：gold set 全量对照通过，不破坏已有期望。
4. **追溯**：每条内容变更记录 source_event 依据，可回滚。

> 推论：gold set 中的盲区标注 = "待验证的迭代需求"，排队等数据，不排队等动手。
> 数据不足时，内容迭代的准入结论是"等待"，不是"添加"。

## 七、工程质量（coding-discipline）

- 先想再写；简洁优先；手术式修改；目标驱动。
- 每个器官必须有可运行的验证集（gold set），迭代后全量回归。
- 测试在临时文件上跑，真实数据零污染。

## 八、版本管理

- git 仓库 `hermes-companion-configs`，复制+提交模式，随时可 revert。
- 敏感信息（key/账号）不入库。
- 每次重大修改后同步 + 提交。

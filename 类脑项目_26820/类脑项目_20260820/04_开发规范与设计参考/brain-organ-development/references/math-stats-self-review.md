# 数学/统计输出自审查清单

> 来源：reflex 事件 #3（-5, 统计逻辑）和 #4（-6, 数学严谨）
> 已写入 reflex-behavior-calibration SKILL.md 的"逻辑严谨红线"规则

## 三步骤（输出前强制过）

### 1. 来源检查

- 这个公式/表达式有确切来源吗？（文档、推导、实验数据）
- 如果是凭记忆写的——停下来，查证。不确定就标 `[!]`。
- 禁止：自己发明不存在的表达式（如 `(α0+k)/(α0+n+k+β0-1)`）然后用"校正为"遮丑。

### 2. 边界检查

- 样本量 n < 30？→ 必须标注"小样本，结论仅供参考"
- 置信区间宽度 > 0.4？→ 必须声明"实际上无信息量"
- "能运行" ≠ "有统计效力"。2 条样本算置信区间 = 瞎扯。

### 3. 标记检查

- 不确定的地方必须显式标记 `[!]` 或 `[待验证]`
- 不能让它混在正文里，假装是确定结论
- 如果以上三步有任何一步未通过，先告知用户限制条件，再给结论

## 典型反例

```
❌ "Bayesian评估器2条真实事件就能起步跑置信区间"
   → 2条样本的95%CI宽度0.6-0.8，等于无信息
❌ Beta后验均值写成 (α0+k)/(α0+n+k+β0-1)
   → 正确公式是 (α0+k)/(α0+β0+n)
❌ 拍脑袋设阈值 0.6
   → 没有校准源，没有实验数据，只是"听起来合理"
```

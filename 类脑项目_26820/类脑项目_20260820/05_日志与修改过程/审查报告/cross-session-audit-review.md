# cross-session-audit-skill 审查意见

> 审查时间：2026-08-12

---

## 1. 描述字段偏"是什么"而非"何时触发"

当前 description：
> 跨会话接手/审查时使用。git log 全量+grep 全库引用+时间线重建三步必做。

对于 Claude Code 的 skill 系统，description 是触发匹配的关键。建议改为面向触发条件：

```yaml
description: 跨会话接手任务、审查旧代码/文档、删除迁移文件前。防记忆过期导致误判——git log全量+grep全库引用+时间线重建三步必做。触发词：接手、上次的、之前的会话、旧的、废弃、迁移、删除文件。
```

---

## 2. 第①步缺少 `git diff` 来发现"差异"

文中提到"对比记忆快照与实际 HEAD：差异 = 其他会话的工作，必须读完再动手"，但没有给出具体的 diff 命令。`git log --oneline -30` 只看提交标题，看不出文件级变更。建议补一行：

```bash
git diff --stat HEAD~10..HEAD   # 看最近10次提交改了哪些文件
```

或者更精确地：

```bash
git diff --name-only <上次本会话记录到的commit> HEAD
```

---

## 3. 第③步不可执行——`session_search()` 不是通用工具

这是 Hermes 系统的自定义函数。在 Claude Code 环境下没有这个能力。建议：

- **要么**改用 Claude Code 可用的替代方案（如对话记录文件路径或 TaskList 查并行会话）
- **要么**标注为 Hermes 专属，并给出降级方案（"若无 session_search，至少比对各会话的 CLAUDE.md/MEMORY.md 中的时间戳"）

---

## 4. 硬编码路径降低可移植性

`~/hermes-companion-configs`、`~/AppData/Local/hermes/skills` 直接写死在命令里。建议在文件头或步骤前声明变量：

```markdown
> **路径约定**: REPO=`~/hermes-companion-configs`, SKILLS=`~/AppData/Local/hermes/skills`
```

然后命令中用 `$REPO` 引用，这样更换环境时只改一处。

当前六维度平铺，但在不同场景下权重不同。比如接手代码时"代码数学"排第一，删除文件时"文档生态"排第一。建议加一列：

| ... | ... | ... |

## 6. 缺少"会话交接"的输出格式

技能说了要做什么，但没说做完后产出什么。建议加一节：

```markdown
## 审计报告输出格式

审查完成后，生成以下结构：

- **交接摘要**: 3-5 句话——谁做了什么、改了哪些文件、我的任务与之有何关联
- **风险点**: 按严重度排列的发现问题列表
- **操作约束**: 基于审查结果，哪些文件/路径不能动、哪些假设已过期
- **LOG.md 条目**: 追加本会话的审查节点
```

---

## 7. 三条可补充的审查维度

基于你列的 bug 模式，缺失了：

- **竞态/冲突审查**：两个并行会话是否改了同一文件？`git log --oneline --all -- <file>` 查交叉修改
- **假设过期审查**：本会话记忆中的"当前状态"是否已被另一会话推翻？（如 "X 已废弃" 这个判断本身是否过期）
- **回滚可达性**：如果本次操作出错，最近的 safe point 在哪？`git reflog` 确认回滚路径
